# DESIGN.md 프로토콜 스펙 v1

PAX 디자인 시스템의 정의 파일 형식. 이 파일 하나가 단일 소스이며, 업로드하면
사람용 가이드 페이지(`/guide/design`)와 AI 조회 도구(웹·로컬 동일)가 여기서 파생된다.

- 기반: [Google Labs DESIGN.md 스펙](https://github.com/google-labs-code/design.md) 의
  "YAML frontmatter 토큰 + 마크다운 본문" 2층 구조. PAX 확장(`themes`, `#### Code`,
  `## Resources`)은 전부 표준 마크다운 문법이라 **외부 도구(Claude Code·Cursor 단독)는
  확장을 몰라도 일반 md 로 그대로 읽을 수 있다**(graceful degradation).
- 파싱은 결정적이다: 지원하지 않는 문법은 조용히 넘기지 않고 **업로드 거절**로 알려준다.
- 크기: 파일 전체 512KB, 컴포넌트 코드 1건 64KB, Usage/Variants 각 16KB, 리소스 본문 100KB.
  개수: 컴포넌트 100·아이템(컴포넌트+리소스) 200·테넌트당 시스템 20.

## 무엇부터 쓸지 — 두 갈래

목적이 다르면 쓰는 부분도 다르다. 섞어 써도 된다.

| 하고 싶은 것 | 쓰는 곳 | 결과 |
|---|---|---|
| **디자인 기준을 기록·공유** (색·서체·컴포넌트 규칙) | frontmatter `tokens` + `## Components` 산문 + **스펙 맵** | 가이드 페이지에 견본·문서가 그려지고, 컴포넌트 코드가 **자동 생성**된다 |
| **이미 있는 코드를 그대로 배포** | `## Components` 의 `#### Code` 펜스 | AI 가 그 코드를 수정 없이 프로젝트에 복사한다 |

앞쪽(스펙 맵)이 디자이너의 주 경로다. 코드를 쓸 줄 몰라도 값만 적으면 견본과 코드가 나온다.
그 방법은 [§ 견본을 풍부하게 만드는 법](#견본을-풍부하게-만드는-법-디자이너-주-경로)에서 다룬다.

## frontmatter 규칙 (YAML 서브셋)

지원: 맵·스칼라(인용/비인용)·N단계 중첩(2칸 들여쓰기 권장, 공백만).
**거절**: 시퀀스(`- `), 앵커/별칭(`&`/`*`), 블록 스칼라(`|`/`>`), 탭 들여쓰기, 중복 키.

- `tokens` 는 `카테고리 → 키 → 값` 맵. 더 깊은 중첩은 `-` 로 평탄화된다
  (`color.brand.accent` → CSS 변수 `--color-brand-accent`).
- **토큰 키**: `^[a-z0-9][a-z0-9-]*$` — 숫자 시작 허용(`2xl` 등, CSS custom property 관례).
- **토큰 값**: 영숫자·공백·`#%.,()'"/-_` 만, 값당 256자
  (세미콜론·중괄호 금지 — 생성되는 design-tokens.css 의 셀렉터 탈출 차단.
  폰트 스택 `'Pretendard', sans-serif` 은 허용).
  추가로 외부 로드 구문(`url(`·`image-set(`·`//`)은 화이트리스트 문자로 조립 가능해도
  거절된다 — 가이드 인라인 스타일·생성 CSS 를 통한 외부 리소스 로드 차단.
- `themes.dark` 는 라이트 토큰의 **오버라이드만** 적는다. 다크 값이 없는 토큰은 라이트 값 유지.
- `tokens` 외 최상위 맵(`components:` 등)은 토큰으로 표현할 수 없는 스펙 블록으로 보고
  참조 문서(`### Spec components`)로 보존한다 — 견본·코드 생성의 입력이 된다.

## 버전은 서버가 올린다

`version` 은 필수지만, **직접 올리지 않아도 된다.** 같은 이름으로 다시 올렸을 때:

| 상황 | 결과 |
|---|---|
| 내용이 같다 | 버전 유지 (재업로드해도 안 올라간다) |
| 내용이 바뀌었다 | **patch +1** (1.2.3 → 1.2.4) |
| frontmatter 에 더 높은 버전을 적었다 | 그 값을 그대로 쓴다 (major·minor 는 이렇게 올린다) |

'내용이 같다'는 판정에서 `version` 줄은 제외한다 — 그래서 다운로드한 파일을 그대로 다시
올려도 버전이 계속 오르지 않는다. 저장되는 정규화본의 `version:` 줄도 확정된 버전으로
맞춰지므로, 화면에 보이는 버전과 내려받은 파일의 버전이 어긋나지 않는다.

## 본문 규칙

- `## Components` / `## Resources` 는 각각 최대 1회. 그 외 H2 섹션(예: `## Principles`)은
  전부 "개요"로 보존된다(후속 `## Assets` 확장의 하위호환 근거).
- 컴포넌트/리소스 이름은 H3 제목에서 영문 슬러그로 생성된다 — **영문 제목 필수**
  (`### Button` → `button`, `### Button Group` → `button-group` → 파일 `ButtonGroup.tsx`).
  슬러그 중복(대소문자 무시)은 거절.
- 컴포넌트 안에서 허용되는 H4 는 `Usage` / `Variants` / `Code` 뿐. 그 외 헤딩은 거절
  (usage/variants 본문에는 헤딩을 쓸 수 없다 — 가이드 렌더 앵커 충돌 방지).
- `#### Code` 를 쓴다면 ```tsx 또는 ```jsx 펜스를 **정확히 1개** 담아야 한다.
  코드 없이 `### 이름` + 산문만 있는 컴포넌트 섹션은 업로드 시 **참조 문서로 이동**한다
  (스펙 산문 보존 — 정규화 단계에서 처리되므로 거절되지 않는다). 그 컴포넌트의 실제
  코드는 스펙 맵에서 자동 생성된다.
- 리소스 본문의 H4 이하 헤딩은 자유(가이드 렌더 시 자동 demote).

### 코드 펜스 문법 (화이트리스트)

- 인정: 행두 0-indent **백틱 정확히 3개** + 단일 언어 토큰(`\`\`\`tsx`). 닫기는 행두 `\`\`\` ` 단독 행.
- **거절**: 틸드(`~~~`) 펜스, 4개 이상 백틱, 닫히지 않은 펜스, 펜스 내부의 또 다른 백틱 펜스 라인.
- 4칸 들여쓰기 코드 블록은 코드로 인정하지 않는다(산문 취급).

# 견본을 풍부하게 만드는 법 (디자이너 주 경로)

가이드의 컴포넌트 견본과 **자동 생성되는 컴포넌트 코드**는 둘 다 **컴포넌트 스펙 맵**에서
나온다. 여기에 엔트리를 추가하면 미리보기·Properties·생성 코드가 함께 늘어난다.

스펙 맵을 쓰는 방법은 두 가지이고 결과는 같다:

```yaml
# ① frontmatter 에 components 맵 (외부 DESIGN.md 와 호환되는 방식)
components:
  button-primary48:
    backgroundColor: "{color.primary}"
    textColor: "#FFFFFF"
    height: "48px"
```

````markdown
<!-- ② Resources 에 직접 (①이 자동 변환되는 형태이기도 하다) -->
## Resources
### Spec components
```yaml
button-primary48:
  backgroundColor: "{color.primary}"
  textColor: "#FFFFFF"
  height: "48px"
```
````

**아무 이름이나 되는 건 아니다** — 이름으로 형태를 판정하고, 이름 꼬리로 축(크기·상태)을 가른다.

## 1. 형태는 **이름**이 정한다

엔트리 이름에 아래 낱말이 들어가면 그 골격으로 그려진다(**위에서부터 먼저 걸리는 것**):

| 낱말 | 그려지는 모습 |
|------|--------------|
| `toggle` · `switch` | ON/OFF 스위치 (클릭 전환) |
| `checkbox` | 체크박스 + 라벨 |
| `radio` | 라디오 + 라벨 |
| `segment` | 세그먼트 컨트롤 (트랙 + 선택 항목) |
| `tab` (단, `table` 제외) | 탭 바 + 인디케이터 |
| `button` · `btn` · `cta` | 버튼 (hover·press 반응) |
| `input` · `field` · `search` | 입력 상자 (타이핑 가능) |
| `badge` · `pill` · `tag` · `chip` | 알약 배지 |
| `cell` · `day` · `avatar` · `swatch` · `dot` | 정사각·원형 셀 (달력 날짜·아바타·색 견본) |
| `nav` · `menu-bar` · `header` | 상단 내비게이션 |
| `card` · `tile` · `listing` · `row` | 카드 |
| `hero` · `band` · `footer` · `banner` | 풀블리드 밴드 |
| (그 외) | 골격 없음 → **AI 가 코드를 대신 생성** |

`popup`·`toast`·`tooltip`·`select`·`table` 처럼 목록에 없는 이름은 스펙만으로는 형태를 못 만들어
업로드 직후 AI 가 코드를 만든다(자동 실행).

### 같은 형태의 다른 컴포넌트는 이름 앞부분으로 갈린다

`button` 과 `icon-button` 은 둘 다 button 형태지만 별개 컴포넌트다. 아키타입에 걸리는
낱말까지가 **기준 이름**이 되고, 기준 이름이 다르면 사이드바에서도 나뉜다.

```yaml
button-primary48:   # 기준 이름 'button'      → Button
icon-button40:      # 기준 이름 'icon-button' → Icon Button (별도 페이지)
```

한 아키타입에 기준 이름이 하나뿐이면 아키타입 이름을 그대로 쓴다(기존 발행본의 이름 유지).

## 2. 크기 축은 **이름 끝 2~3자리 숫자**

```yaml
button-primary48:   # → SIZE 축 '48'
button-primary32:   # → SIZE 축 '32'
button-primary-lg:  # → SIZE 아님. VARIANT 'primary-lg' 로 잡힌다
```

숫자로 끝내면 Properties 의 **SIZE** 그리드에 크기순으로 늘어선다. 개수 제한 없음 —
15종을 넣으면 15칸이 실제 높이대로 그려지고, 생성 코드의 `ButtonSize` 타입에도 15종이 들어간다.

## 3. 상태 축은 **정해진 접미사**

`-hover` · `-active` · `-pressed` · `-focus` · `-disabled` · `-selected`

```yaml
button-primary-hover:
  backgroundColor: "#1458ad"   # 바뀌는 값만 적으면 base 를 상속한다
```

이 여섯 개만 **STATE** 그리드로 간다. 다른 접미사(`-error`, `-warning` 등)는 변형으로 취급된다.

## 4. 나머지는 전부 **변형(VARIANT)**

```yaml
button-primary:  …   # VARIANT 'primary'
button-ai:       …   # VARIANT 'ai'
button-delete:   …   # VARIANT 'delete'
```

## 5. 화면에 반영되는 속성

| 키 | 쓰임 |
|----|------|
| `backgroundColor` | 면 색 |
| `textColor` | 글자 색 |
| `borderColor` | 테두리 색 (있으면 1px 실선) |
| `height` · `width` | 실제 치수 (견본이 이 크기로 그려짐) |
| `size` | 정사각 치수 한 값 (`height`·`width` 를 동시에 지정한 것과 같음) |
| `padding` | 안쪽 여백 |
| `rounded` (또는 `radius`) | 모서리 |
| `typography` | `{typography.body2}` 처럼 토큰 참조 → 크기·굵기·행간·자간 |

값은 hex 직접 입력도 되고 `{colors.accent-normal}` 참조도 된다. **토큰 참조를 쓰면
리브랜딩 때 견본까지 자동으로 따라온다** — 되도록 참조를 권한다.

## 6. 치수가 형태를 바꾸는 세 경우

값만 보고 형태를 다르게 그리는 규칙이 있다. 의도와 다르게 나오면 대개 여기에 걸린 것이다.

- **정사각이면 아이콘 전용** — `width ≈ height`(오차 2px) 인 버튼은 라벨 대신 아이콘 자리로
  그린다. 40×40 짜리에 "저장" 같은 라벨을 넣으면 글자가 세로로 쌓이기 때문이다.
  한 컴포넌트의 엔트리가 **전부** 정사각이면 그 컴포넌트는 아이콘 전용으로 보고,
  AI 가 붙인 변형 라벨도 아이콘으로 대체한다.
- **정사각 + 80px 이하면 아이콘 타일** — 이름이 아키타입에 안 걸려 카드로 떨어진 엔트리라도
  `size: 48px` 처럼 작은 정사각이면 카드가 아니라 아이콘 버튼으로 그린다
  (`carousel-arrow` 같은 원형 화살표).
- **높이 20px 미만이면 선** — `m-stripe-divider`(4px) 처럼 얇은 스펙은 글자를 담을 수
  없으므로 선 자체로 그린다. 같은 이유로 20px 미만 셀(`status-dot` 8px)은 점으로만 그린다.

## 7. 카드는 **이름이 내용까지 정한다**

카드 아키타입은 이름에서 용도를 읽어 안쪽 골격을 바꾼다. 전부 "제목 + 본문"으로만 그리면
시스템이 달라도 같은 그림이 나오기 때문이다.

| 이름에 들어가는 낱말 | 카드 안에 그려지는 것 |
|---|---|
| `empty` · `placeholder` · `blank` · `no-data` | 빈 상태 (점선 자리표시 + 안내문) |
| `photo` · `image` · `thumb` · `pin` · `tile` · `media` · `cover` · `gallery` | 상단 이미지 영역 + 제목·본문 |
| `stat` · `metric` · `number` · `count` · `score` · `rating` | 큰 수치 + 지표 이름 + 증감 |
| `step` · `stage` · `process` · `phase` | 원형 번호 + 단계 제목 |
| `rank` · `leaderboard` · `-row` · `list-item` | 순위 + 썸네일 + 2줄 (가로 배치) |
| `auth` · `login` · `signup` · `form` · `input` | 라벨 + 입력칸 2개 + 버튼 |
| `modal` · `dialog` · `popup` · `sheet` | 제목 + 본문 + 취소/확인 버튼 |
| (그 외) | 제목 + 본문 |

밴드(`hero`·`banner` 등)에는 CTA 칩이 하나 붙는다.

## 8. 설명·사용 규칙은 어디서 오나

견본 옆의 설명(용도·권장·피하기·접근성·Props)은 **`## Components` 산문**과 스펙 값을 근거로
업로드 직후 AI 가 채운다. 산문을 자세히 쓸수록 문서가 충실해진다. 규약은 문단을 컴포넌트
이름 코드로 시작하는 것:

```markdown
**`toast`** — 응답이 필요 없는 알림 전용, 3초 자동 닫힘. 안에 버튼·링크 금지…
```

이렇게 쓰면 그 문단이 Toast 컴포넌트 페이지로 자동 배정된다.

AI 가 채운 결과는 컴포넌트 코드를 건드리지 않는다(문서만 보강). 재업로드해도 AI 산출물은
보존되고, 스펙에서 결정적으로 생성된 코드만 새로 만들어진다.

## 9. 자주 하는 실수

- **크기를 `-sm`/`-lg` 로** → SIZE 축이 아니라 변형으로 잡혀 크기 비교가 안 된다. 숫자를 쓴다
- **`table` 에 `tab` 이 들어간다고 탭으로 잡히지 않는다** — `tab(?!le)` 로 걸러진다
- **변형끼리 값이 같으면** 화면에서 구분이 안 된다. 채움·테두리·모서리·크기 중 하나는 달라야 한다
- **`height` 없이 `padding` 만** 주면 견본 높이가 글자 크기로 결정돼 크기 차이가 흐려진다
- **아이콘 버튼에 `width` 를 빼먹으면** 정사각으로 안 잡혀 라벨이 들어간다 — `size` 를 쓰거나
  `width`·`height` 를 함께 적는다

## 업로드 검증 (거절 사유)

업로드 시 3계층 검증을 통과해야 하며, 실패 항목은 전부 한 번에 목록으로 반환된다.

1. **산문 계층**(개요·설명·Usage/Variants·리소스 산문): 프롬프트 인젝션 패턴,
   펜스 위조 문자열(`<untrusted…`, 스킬 샌드박스 마커), 채팅 템플릿 토큰 거절.
2. **코드 계층**(컴포넌트 코드·리소스 내 코드 펜스): 시크릿(고신뢰 패턴 — API 키·JWT·
   자격증명 URL 등) 검출 시 거절(마스킹하지 않는다), 펜스 위조·채팅 템플릿 토큰 거절.
   일반 코드 문자열(`api_call` 등)은 산문 계층과 달리 허용된다.
3. **frontmatter 스칼라 계층**: 토큰 키/값 형식(위 규칙).

시크릿 스캔은 파일 **전문**에 적용된다 — 산문에 붙여넣은 키도 거절된다.
기존 파일을 fork 해 재업로드할 때 코드 상단의 `// @design-system …` 주석(provenance)은
자동으로 제거되니 지우지 않고 올려도 된다.

거절과 별개로, 업로드 성공본에는 **advisory 품질 진단**(자체 결정적 린트 —
primary 누락·다크 배경/글자 짝 깨짐·WCAG 대비 미달·hex 하드코딩·카테고리 오타 제안)이
응답에 동봉된다. 진단은 등록·발행을 막지 않는다. PAX 웹 호스트 한정으로,
거절된 파일은 테넌트 AI 키로 **자동 AI 교정**(1회)을 시도하고, md 여러 개를 함께
올리면 자료 전체에서 실제 값을 추출해 DESIGN.md 를 **AI 조립**한다 — 산출물도
동일한 검증 레일을 재통과해야 하며 초안(draft)으로만 등록된다.

## 소비 규약 (AI·가이드가 이 파일을 쓰는 방식)

- **토큰** → `styles/design-tokens.css` (`:root { --카테고리-키: 값 }` + `[data-theme="dark"] { … }`).
  생성 코드에서 색·간격은 `var(--…)` 변수만 사용.
  배선은 **`app/layout.tsx` 최상단 side-effect import 한 번**
  (`import '@/styles/design-tokens.css'`) — 앱 전체 페이지에 적용된다. 페이지별 배선은
  새 페이지 누락 → 토큰 전무 → 화면 붕괴의 원인이라 금지(2026-08-26). 미리보기(Sandpack)는
  layout 을 평가하지 않지만 씬 엔트리가 layout 의 CSS import 를 자동 주입한다.
- **컴포넌트 코드** → `components/design/{PascalCase}.tsx` 에 **수정 없이 그대로** 복사.
  코드 작성 규약: 클라이언트 컴포넌트만, 서버 전용 import(`next/headers`·`fs` 등) 금지
  (Sandpack 미리보기가 평가할 수 없는 코드는 미리보기에서 깨진다).
- **컴포넌트 코드의 출처는 셋** — ① `#### Code` 에 직접 쓴 것 ② 스펙 맵에서 결정적으로
  생성된 것(AI·네트워크 불필요) ③ 골격이 없는 이름을 AI 가 생성한 것. 같은 이름이면
  ①이 항상 우선한다. 재업로드 시 ②만 새로 만들어지고 ①③은 보존된다.
- **가이드 견본은 코드를 실행하지 않는다** — 우리가 가진 골격에 검증된 값만 입혀 그린다.
  업로드된 코드를 브라우저에서 평가하면 올린 사람이 관리자 세션 권한으로 임의 스크립트를
  실행하는 셈이라(저장형 XSS), 견본과 실제 컴포넌트는 **다른 경로**다. 값·치수는 같지만
  마크업 세부는 다를 수 있다.
- **발행 게이트 (호스트별로 다름)**: PAX 웹은 2단계 — 업로드 직후는 초안(draft)이며
  관리자가 발행해야 AI·가이드에 반영된다. 발행 중인 시스템에 같은 이름을 재업로드하면
  관리자 확인 창에서 **발행 유지 교체**(`keepPublished`)를 고를 수 있다 — 검토 단계 없이 즉시
  교체되고, 실패하면 초안으로 강등된다. 검토 후 발행하려면 철회 → 업로드. AI 교정·조립
  산출물은 항상 초안이다. **PDS(스탠드얼론)은 검증 통과 = 즉시 발행**이며
  가이드 페이지가 무인증 공개다 — 작업 중(WIP) 파일은 킷에 올리지 않는 것을 권장.
- **재동기화 (첫 줄 hash)**: 토큰 CSS 는 첫 줄 `/* @design-system {name}@{version} hash:{12자} … */`,
  저장형 컴포넌트는 첫 줄 `// @design-system … hash:` provenance 헤더를 갖는다. 소비자는 파일이
  이미 있으면 첫 줄 hash 를 받은 것과 비교해 같으면 그대로 두고, 다르거나 헤더가 없으면 통째로
  덮어쓴다(발행본 갱신 반영, 낡은 사본 위에 손으로 보완하지 않는다).
- **배달 판정**: `#### Code` 가 컴포넌트를 정의하면(`export default …`) 파일로 저장하고, 외부
  패키지 import 는 `dependencies` 로 함께 안내한다. 정의 없이 패키지 import + JSX 만 있는 조각은
  사용 예제로 보고 패키지 설치(`install`)로 안내한다 — 저장하지 않는다.
- **AI 스킬 zip**: 발행본은 가이드 페이지(리소스 > 다운로드)에서 자급형 스킬
  `{name}-design-skill.zip`(SKILL.md + references/ 컴포넌트 코드 [+ assets/ 로고])으로
  내려받을 수 있다 — AI 코딩 도구의 스킬 폴더(예: `.claude/skills/`)에 압축 해제.
  재발행하면 zip 도 새 발행 해시 기준으로 갱신된다(구본은 서빙되지 않음).

## 브랜드 에셋 (v1: md 밖 관리)

로고는 DESIGN.md 본문이 아니라 **관리자 화면(시스템 상세 > 브랜드 로고)에서 별도
업로드**한다(SVG 전용·라이트/다크 슬롯). md 재업로드와 독립적으로 유지되고,
노출은 발행 상태를 따른다. 가이드 네비·푸터 렌더와 스킬 zip 의 `assets/` 동봉에
사용된다. md 안 참조 문법(`## Assets`)은 후속 확장.

## 외부 DESIGN.md 가져오기 (자동 호환)

getdesign.md(awesome-design-md) 등 외부 생태계의 DESIGN.md 는 **원본 그대로 업로드**하면
서버가 자동으로 우리 프로토콜에 맞춰 등록한다(무엇을 바꿨는지 알림으로 표시):

- 이름·버전 형식 자동 정규화 (원문 이름은 표시 제목으로 보존)
- `tokens:` 없이 최상위에 둔 `colors:`/`typography:` 등 카테고리 → tokens 아래로 이동,
  camelCase 키 → kebab-case (`canvasSoft` → `canvas-soft`)
- 교차참조 `{colors.primary}` → 실제 값으로 치환. 맵 참조가 섞여 토큰으로 표현할 수 없는
  스펙 블록(frontmatter `components:` 등)은 참조 문서(YAML)로 보존 — 데이터 소실 없음
- 구현 코드가 없는 컴포넌트 섹션 → 참조 문서로 이동 (스펙 산문 보존).
  그 컴포넌트의 코드는 스펙 맵에서 자동 생성되고, `#### Code` 를 직접 추가하면 그쪽이 이긴다

우리 형식 파일에는 아무 변환도 일어나지 않으며, 보안 검증은 정규화 이후 동일하게 적용된다.

## 알려진 한계 (v1)

- **다크 모드 활성화 경로**: 생성된 CSS 의 다크 블록은 `[data-theme="dark"]` 속성 셀렉터다
  (2026-08-26 `.dark` 클래스에서 전환 — 미리보기 토글·생성 앱 프롬프트·PDS 패키지가 전부
  `data-theme` 을 쓰므로 규약을 하나로 맞췄다). 앱은 `<html data-theme="dark">` 로 켠다.
- 에셋의 **md 내 참조 문법**은 v1 미정의 — 로고는 관리자 화면 업로드로 지원되며(위 절),
  md 안 선언(`## Assets`)·폰트·아이콘은 후속 규약으로 확장 예정.
- **AI 미리보기 명세는 한 층짜리**(`bg`/`fg`/`border`/`accent`)라, 세그먼트(트랙 + 선택 알약)나
  팝업(패널 + 내부 버튼)처럼 2층인 컴포넌트는 어느 층의 색인지 모호할 수 있다. 렌더러가
  값이 읽히지 않는 조합을 교정하지만, 정확한 결과를 원하면 스펙 맵에 값을 직접 적는 편이 낫다.
- 아키타입 판정은 **영문 낱말 기준**이다. 한글 이름 엔트리는 골격을 못 찾아 AI 생성 경로로 간다.
